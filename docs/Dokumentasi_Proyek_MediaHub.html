Laporan ini mendokumentasikan tahapan pengerjaan, fungsi modul, integrasi Firebase, serta cuplikan source code aplikasi.

Tools yang Digunakan

Pengembangan MediaHub menggunakan Flutter dan Dart untuk aplikasi Android serta Firebase sebagai layanan backend.

  • Flutter SDK dan Dart SDK untuk membangun aplikasi lintas platform.
  • Cloud Firestore untuk penyimpanan metadata media dan data users.
  • Firebase Core untuk inisialisasi layanan Firebase.
  • just_audio dan video_player untuk pemutaran media; youtube_player_flutter untuk video YouTube.
  • photo_manager untuk membaca media pada perangkat Android dan url_launcher untuk membuka tautan eksternal.
  • Visual Studio Code, Android SDK, emulator Android, atau perangkat Android untuk pengembangan dan penggunaan.

Tahap Pengerjaan

Tahap 1 — Menyiapkan struktur aplikasi dan Firebase

Struktur proyek dipisahkan berdasarkan fungsi. main.dart mengatur tema Material 3, menginisialisasi Firebase, menyiapkan repository, dan membuka navigasi utama. Layar aplikasi kemudian dibagi menjadi Home, Audio, Video, Library, Search, Profile, dan CRUD Users. Pola ini menjaga tampilan, model data, akses database, dan pemutar media tetap terpisah.

Firebase bootstrap → navigasi utama → modul Audio / Video / Library / Search / Profile
Home → CRUD Users → koleksi Firestore users
Library → Cloud Library → koleksi Firestore songs

Tahap 2 — Menyiapkan katalog dan model media

Model MediaItem menyatukan informasi media untuk katalog dan player. Properti type membedakan audio dan video; sourceType membedakan aset aplikasi, URL network, dan media perangkat. Katalog bundel di lib/media/media_catalog.dart mendaftarkan lagu dan video lokal, termasuk video assets/video/rude_mv.mp4.

Informasi koleksi media diserialisasi ke Firestore dengan field title, creator, type, description, category, sourceType, mediaUrl, thumbnailUrl, createdAt, dan updatedAt.

Tahap 3 — Menghubungkan Cloud Library dengan Firestore

Cloud Library menggunakan FirestoreMediaRepository untuk membaca koleksi root songs dan menjalankan CRUD metadata. Stream Firestore menjaga daftar pada layar tetap mengikuti perubahan yang diterima aplikasi. Formulir media menangani tambah maupun edit; halaman daftar dan detail menyediakan akses ke item yang dipilih. File media sendiri tidak diunggah ke Firestore Storage oleh aplikasi.

Tahap 4 — Membuat fitur CRUD Users

Halaman CRUD Users membaca, menambah, mengubah, serta menghapus dokumen pada koleksi root users. Formulir menggunakan field nama, email, dan kelas. Penamaan nama harus sama persis dengan nama field pada dokumen Firestore; sebelumnya ketidaksesuaian dengan field name menyebabkan data gagal dipetakan dengan benar.

Model mempertahankan record dengan field yang kosong atau salah tipe, lalu menandainya agar dapat diperbaiki pengguna. Waktu pembuatan dan perubahan dicatat memakai server timestamp.

Tahap 5 — Menambahkan pemutar audio dan video

Player audio memilih setAsset untuk media bundel dan setUrl untuk media network atau URI perangkat. Player video menggunakan controller sesuai sumber, menyediakan pengelolaan lifecycle, penanganan error, kontrol playback, dan mode layar penuh.

Tahap 6 — Mengakses media perangkat dan layanan YouTube

Pemindaian media perangkat meminta izin yang sesuai dengan tipe audio atau video, membaca MediaStore secara berhalaman, lalu mengubah hasilnya menjadi MediaItem. Video YouTube menggunakan player tersendiri; URL YouTube divalidasi sebelum ID video dikirim ke player.

Tahap 7 — Menambahkan pencarian dan navigasi fitur

Search memfilter katalog bundel menurut judul, kreator, dan kategori. Layar Home, Audio, Video, Library, Profile, dan Search menjadi pintu masuk fitur, sedangkan media_navigation.dart menghubungkan kartu media dengan player yang sesuai.

Struktur data Firestore

KoleksiField yang digunakan aplikasiKeterangan
songstitle, creator, type, description, category, sourceType, mediaUrl, thumbnailUrl, createdAt, updatedAtMetadata media Cloud Library; mediaUrl menunjuk aset yang tersedia atau URL media.
usersnama, email, kelas, createdAt, updatedAtData CRUD Users bersama. Field nama ditulis tepat sebagai nama.
playlistBelum ditentukan oleh antarmuka aplikasi.Koleksi dicakup rules, tetapi belum memiliki halaman dan schema aplikasi.

Field inti songs memakai string untuk judul, kreator, jenis media, sumber, dan URL media; timestamp mencatat waktu dokumen. Koleksi users memakai string untuk nama, email, dan kelas beserta timestamp. ID dokumen Firestore digunakan untuk operasi edit dan hapus.

Konfigurasi akses Firestore: Aplikasi tidak menggunakan Firebase Authentication. Berdasarkan konfigurasi yang dipilih, client dapat mengakses data bersama tanpa login sesuai koleksi yang diizinkan Firestore Rules. Rules perlu diterapkan melalui Firebase Console. Hindari menyimpan data sensitif pada koleksi publik.

Pengguna mengonfirmasi koneksi Firestore dan CRUD telah berjalan pada konfigurasi project saat ini. Project Firebase yang dicatat pada konfigurasi aplikasi adalah mediahubs-bbf06; application ID Android com.mediahubs.uts0035.

Media bundel, perangkat, dan Android

Media audio dan video contoh disertakan sebagai asset aplikasi, termasuk assets/video/rude_mv.mp4. Audio/video yang berada di perangkat pengguna dibaca lokal dan tidak disalin, dihapus, atau diunggah aplikasi. Media network memerlukan URL yang dapat diakses oleh player; URL halaman YouTube diproses pada player YouTube khusus.

Aplikasi mendeklarasikan akses internet dan izin Android untuk media audio/video, termasuk jalur akses terbatas pada Android baru dan kompatibilitas versi lebih lama. Izin diminta ketika fitur pemindaian media digunakan.

Konfigurasi proyek

  1. Daftarkan aplikasi Android dengan application ID com.mediahubs.uts0035 pada Firebase project yang digunakan.
  2. Letakkan file google-services.json yang sesuai pada android/app/ dan aktifkan Cloud Firestore.
  3. Tinjau dan terapkan docs/firestore.rules.example melalui Firebase Console sesuai kebutuhan database.
  4. Pastikan aset di direktori assets/ terdaftar pada pubspec.yaml.
  5. Jalankan aplikasi dengan flutter pub get, pilih perangkat Android, lalu flutter run. Paket rilis dapat dibuat melalui flutter build apk --release.

APK release Flutter berada di build/app/outputs/flutter-apk/app-release.apk.

Hak aset dan batasan fitur

Media metadata tersimpan di Firestore, sedangkan biner media tidak memakai Firebase Storage. Pencarian saat ini mencakup katalog bundel. Koleksi playlist memiliki akses pada Rules tetapi belum mempunyai antarmuka dan model data dalam aplikasi. Pastikan hak penggunaan MP3, MP4, logo, dan gambar sebelum distribusi; rincian dependency serta lisensi dicatat pada LICENSES.md.

Dokumen teknis terkait meliputi docs/PRD.md, docs/IMPLEMENTATION.md, dan docs/firestore.rules.example.

Kesimpulan

MediaHub merupakan aplikasi Android berbasis Flutter yang menggabungkan katalog audio/video, pemutar media, pemindaian media perangkat, pencarian katalog, dan manajemen metadata berbasis Cloud Firestore. Pemisahan layar, model, repository, dan player membantu tiap fitur memiliki tanggung jawab yang jelas.

Dokumentasi ini mengikuti tahapan laporan proyek, merangkum fungsi seluruh 27 file Dart, serta menyertakan cuplikan kode yang berkaitan langsung dengan fungsi dan nama file asalnya.
