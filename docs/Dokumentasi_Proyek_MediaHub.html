1. Tools dan Teknologi

MediaHub adalah aplikasi katalog dan pemutar media pribadi. Metadata media disimpan terpisah dari berkas audio/video. Aplikasi menargetkan Android untuk demonstrasi UTS.

TeknologiPenggunaan

Firebase Core, Auth, FirestoreInisialisasi Firebase, Anonymous Authentication, dan katalog metadata per pengguna.

Dependency yang ter-resolve tercatat pada pubspec.lock. Firebase Console harus mengaktifkan Anonymous sign-in dan menerapkan Rules yang ditinjau sebelum operasi cloud berhasil.

2. Tahap Pengerjaan

Tahap 1 — Struktur proyek dan navigasi

Proyek dibagi ke direktori fitur seperti home/, audio/, video/, library/, media/, dan player/. Navigasi utama menggunakan Home, Audio, Video, Library, dan Profile.

Tahap 2 — Katalog dan aset lokal

Katalog demo mengacu pada lima lagu MP3 dan satu video MP4. Path video yang digunakan pada kode dan berkas adalah:

assets/video/Hearts2Hearts 하츠투하츠 'RUDE!' MV.mp4

Karakter Hangul pada basename: U+D558 U+CE20 U+D22C U+D558 U+CE20.

Path tersebut kini didaftarkan secara eksplisit di pubspec.yaml. Pemeriksaan menemukan bahwa assertion lama pada widget test menggunakan nama ASCII yang tidak ada; assertion diselaraskan ke nama berkas aktual.

Tahap 3 — Pemutar video

VideoPlayerScreen memakai VideoPlayerController.asset untuk video bundel. Layar menyediakan loading, error dan coba lagi, play/pause, progress, seek, fullscreen, serta pelepasan controller saat layar ditutup.

Pemeriksaan statis pada kontainer menemukan AVC/H.264 Main Profile Level 3.1, penanda AAC, dan atom moov sebelum mdat. Pemeriksaan ini membantu diagnosis format berkas, tetapi tidak membuktikan kompatibilitas decoder pada perangkat tertentu.

Status pemutaran: belum ada APK baru yang berhasil dibuat dan dipasang untuk memverifikasi playback pada Android. APK lama mungkin masih membawa asset manifest/path versi sebelumnya.

3. Integrasi Firestore dan CRUD

Repository Firestore mengimplementasikan operasi baca, tambah, ubah, dan hapus. Daftar memakai stream realtime. Create menetapkan timestamp server; update mempertahankan createdAt dan memperbarui updatedAt.

OperasiPerilaku aplikasi
ReadStream item dari users/{uid}/media; tampilkan loading, kosong, dan error.
CreateForm memvalidasi judul, kreator, jenis, sumber dan URL/path.
UpdateForm edit memuat metadata lama dan mempertahankan waktu pembuatan.
DeleteDialog konfirmasi sebelum dokumen cloud dihapus.

Aturan keamanan

Contoh aturan berada di docs/firestore.rules.example. Akses hanya diizinkan untuk sesi anonim dengan UID yang sama; field dan tipe data divalidasi. Aturan tersebut belum diterapkan ke proyek Firebase.

Tindakan Firebase yang diperlukan: di Firebase Console aktifkan Anonymous Authentication, pastikan database Firestore tersedia, lalu tinjau dan terapkan Rules contoh. Sampai langkah tersebut dilakukan, operasi cloud dapat menerima permission-denied.

Dokumen di koleksi root lama tidak dimigrasikan. Data baru memakai path per UID. Berkas media tetap berada di aset aplikasi atau sumber URL; metadata cloud tidak berarti media sudah diunduh untuk penggunaan offline.

5. Kesimpulan

MediaHub menggabungkan katalog aset lokal, pemutar audio/video, pemindaian media Android, dan kode CRUD Firestore per pengguna anonim. Path video aktual sudah diselaraskan antara aset, deklarasi Flutter, katalog, tes, dan dokumentasi. Pemeriksaan statis MP4 menunjukkan penanda codec H.264 dan AAC yang lazim untuk Android.

Namun, pemutaran pada perangkat dan akses Firestore belum dapat dinyatakan berhasil. Build Flutter terakhir timeout dan tidak ada Gradle wrapper lokal. Langkah berikutnya adalah menyiapkan Firebase Console, membangun APK baru, lalu merekam hasil uji aktual.

Catatan hak penggunaan. Lisensi MP4, lagu, foto profil, dan logo belum terdokumentasi. Lihat LICENSES.md; jangan membagikan media atau APK sebelum hak distribusinya dipastikan.
