1. Tools dan Teknologi

MediaHub adalah aplikasi katalog dan pemutar media pribadi. Metadata media disimpan terpisah dari berkas audio/video. Aplikasi menargetkan Android untuk demonstrasi UTS.

TeknologiPenggunaan
Flutter dan DartUI Material 3, navigasi, formulir, dan logika aplikasi.
Firebase Core dan FirestoreInisialisasi Firebase dan katalog metadata bersama tanpa Authentication.

video_playerPemutar video dari aset, URL langsung, atau URI perangkat.
photo_managerPemindaian media Android dengan izin pengguna.
Android Studio / VS CodePengembangan dan inspeksi proyek.

Akses publik tanpa login. Semua client dapat membaca, menambah, mengubah, atau menghapus record pada koleksi tersebut. Validasi Rules membatasi bentuk data, bukan identitas pemilik. Jangan simpan data privat.

Dependency yang ter-resolve tercatat pada pubspec.lock. Buat database Firestore dan publish Rules contoh setelah ditinjau.

2. Tahap Pengerjaan

Tahap 1 — Struktur proyek dan navigasi

Proyek dibagi ke direktori fitur seperti home/, audio/, video/, library/, media/, dan player/. Navigasi utama menggunakan Home, Audio, Video, Library, dan Profile.

Tahap 2 — Katalog dan aset lokal

Katalog demo mengacu pada lima lagu MP3 dan satu video MP4. Path video yang digunakan pada kode dan berkas adalah:

assets/video/rude_mv.mp4

Path tersebut cocok dengan berkas di repository dan didaftarkan melalui direktori assets/video/ di pubspec.yaml.

Tahap 3 — Pemutar video

VideoPlayerScreen memakai VideoPlayerController.asset untuk video bundel. Layar menyediakan loading, error dan coba lagi, play/pause, progress, seek, fullscreen, serta pelepasan controller saat layar ditutup.

Pemeriksaan statis pada kontainer menemukan AVC/H.264 Main Profile Level 3.1, penanda AAC, dan atom moov sebelum mdat. Pemeriksaan ini membantu diagnosis format berkas, tetapi tidak membuktikan kompatibilitas decoder pada perangkat tertentu.

Status pemutaran: belum ada APK baru yang berhasil dibuat dan dipasang untuk memverifikasi playback pada Android. APK lama mungkin masih membawa asset manifest/path versi sebelumnya.

3. Integrasi Firestore dan CRUD

Repository Firestore mengimplementasikan operasi baca, tambah, ubah, dan hapus tanpa Firebase Authentication. Daftar memakai stream realtime. Create menetapkan timestamp server; update mempertahankan createdAt dan memperbarui updatedAt.

OperasiPerilaku aplikasi
ReadStream item dari koleksi root media; tampilkan loading, kosong, dan error.
CreateForm memvalidasi judul, kreator, jenis, sumber dan URL/path.
UpdateForm edit memuat metadata lama dan mempertahankan waktu pembuatan.
DeleteDialog konfirmasi sebelum dokumen cloud dihapus.

Aturan keamanan

Contoh aturan berada di docs/firestore.rules.example. Rules memberi akses publik pada koleksi root media dan users, dengan validasi field dan timestamp. Aturan tersebut harus ditinjau dan diterapkan ke proyek Firebase.

Tindakan Firebase yang diperlukan: pastikan database Firestore tersedia, lalu tinjau dan publish Rules contoh. Siapa pun yang memiliki akses sebagai client dapat membaca serta mengubah record pada kedua koleksi.

Data media lama di subkoleksi users/{uid}/media tidak otomatis dipindahkan ke koleksi root media. Firebase Storage belum diintegrasikan; berkas media tetap berada di aset aplikasi atau sumber URL.

5. Kesimpulan

MediaHub menggabungkan katalog aset lokal, pemutar audio/video, pemindaian media Android, dan CRUD Firestore bersama tanpa Authentication. Koleksi media dan users dapat diakses oleh semua client; Rules hanya memvalidasi bentuk record. Path video aktual sudah diselaraskan antara aset, deklarasi Flutter, katalog, tes, dan dokumentasi.

Akses Firestore tanpa login dan pemutaran video belum dapat dinyatakan berhasil sampai Rules diterapkan dan APK terbaru diuji. APK release sudah berhasil dibangun; langkah berikutnya adalah meninjau Rules, memasang APK, lalu merekam hasil CRUD aktual.

Catatan hak penggunaan. Lisensi MP4, lagu, foto profil, dan logo belum terdokumentasi. Lihat LICENSES.md; jangan membagikan media atau APK sebelum hak distribusinya dipastikan.
